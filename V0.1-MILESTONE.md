# Edo Tensei v0.1 milestone

Status: validated core milestone on Ubuntu 24.04 x86_64 with an NVIDIA H100
80GB, driver 570.211.01, CUDA 12.8, CRIU 4.2.1, and Linux checkpoint support.

## What is included

- Capability discovery through `edo doctor`.
- CPU-only CRIU dump/restore with process identity validation.
- CUDA 12.8 dynamic checkpoint FFI.
- CUDA state polling and error-name reporting.
- CUDA-before-CRIU `freeze` orchestration.
- CRIU-first `summon`, followed by CUDA restore and unlock.
- Rollback when CRIU dump fails.
- Native CUDA fixture and GPU checksum verification.
- Hugging Face Qwen GPU model snapshot demo using a dedicated CUDA Conda/uv environment.
- Real vLLM API-parent plus `VLLM::EngineCore` group dump/restore with a
  post-restore serving request.

## Validated state transitions

```text
CUDA RUNNING
  → LOCKED
  → CHECKPOINTED
  → CRIU DUMP
  → CRIU RESTORE
  → CUDA RESTORE and LOCKED
  → UNLOCKED and RUNNING
```

## Results

### Native GPU model allocation

For a 512 MiB CUDA-resident model-sized tensor:

- Freeze: 2.043 seconds.
- Restore: 1.534 seconds.
- GPU checksum before and after: `17193905543863665539`.

### Hugging Face Qwen 0.5B Instruct

Loaded directly onto the H100 with CUDA-enabled PyTorch:

- Parameters: 494,032,768.
- Cold model startup including warmup: 18.178 seconds.
- Freeze: 3.674 seconds.
- Restore: 3.068 seconds.
- GPU checksum before and after:
  `03f15156e5c2f9fbb01d0bedca483f5b96182b5f19fb2d512e3c5ac5bdd7280f`.
- Warmup generation completed before snapshot and model state remained valid after restore.

## v0.1 boundaries

- Frameworks must provide application-level request draining/quiescence before
  calling `edo freeze`; Edo cannot infer in-flight work from an arbitrary PID.
- The local implementation targets one Linux process and one NVIDIA GPU.
- Cross-host migration, distributed workers, and multi-GPU coordination are
  not included in this milestone. The validated vLLM adapter remains a focused
  one-GPU, tensor-parallel-size-1 prototype.
- The Qwen demo reproduces the GPU snapshot workflow locally; it does not claim
  to reproduce Modal's managed gVisor, distributed filesystem, or worker cache.
